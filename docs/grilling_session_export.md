### Testing Methodology

1. Run once per transcript (topic-jump runs twice for variance check)
2. Manual review of output + `pedagogical_reason` — human judgment on 2–3 samples
3. Wide-band automated smoke tests:
   - Banter score < 50
   - Positive control score > 70
   - Topic-jump: run twice, note variance
4. Capture raw LLM output before schema validation — check duration compliance
5. Log known limitations in `e2e_results.md`

### Duration Compliance Measurement

The test measures how many LLM-proposed durations fall outside 25–75s **before** schema validation runs:

- `outOfRangeCount` = clips where `duration < 25` or `duration > 75`
- Logged in `e2e_results.md` as: "Of N live proposals, M were within-range pre-validation; X required schema rejection."
- 0 rejections = prompt effective; >20% = prompt needs attention

## RFC-C3-04: Segment Duration Policy

### Decision

The 25–75s window is **already enforced at three layers** — defense-in-depth, not duplication:

1. **Prompt-level** (`curation_prompt.md` line 33): "Duranasi: Setiap clip harus 25-75 detik"
2. **Schema-level** (`clip-output-schema.js` line 6): `Joi.number().min(25).max(75).required()`
3. **Service-level** (`curation.service.js` line 63): `buildPrompt()` reinforces the constraint

### Why Three Layers

Each layer catches a different failure mode:
- Prompt wording can be ignored by the LLM (non-deterministic)
- Schema validation can be bypassed if someone changes the Joi schema
- Service-layer prompt ensures the instruction survives refactoring of the standalone prompt file

### Code Changes

**None.** Documentation only.
